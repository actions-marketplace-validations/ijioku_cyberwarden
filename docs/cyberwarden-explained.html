1. What CyberWarden does

CyberWarden reads the files in a project folder and looks for common security mistakes. It works like a careful inspector walking through a building: it doesn't break in, it points at the unlocked windows.

For every problem it finds, it tells you:

  • What's wrong, in plain English, and the exact file and line.
  • Why it matters: what an attacker, or a misbehaving AI, could do with it.
  • How to fix it, with a before-and-after example. Some fixes can be applied automatically after you review them.
  • How serious it is: critical, high, medium, low or info.

Then it adds everything up into a score out of 100 and a grade from A to F, and can make an offline dashboard you can share with your team or a client.

What it scans

  • Your AI coding setup. Tools like Claude Code, Codex, Gemini CLI, Cursor and OpenCode are controlled by settings files, instruction files (like CLAUDE.md), hooks, MCP servers, skills and agents. A mistake in any of these can give an AI, or someone who tricks it, far more power over your computer than you meant to.
  • Your website or web app code (when you turn on --web): the login, payments, database queries, forms, webhooks and AI chat features that real visitors use.

What it doesn't do

  • It doesn't send your code anywhere. The scan runs on your own computer, and the dashboard works offline.
  • It never reads the secrets inside your .env file. It only checks the file's name and whether git ignores it.
  • It doesn't attack your live site. It reads code; it doesn't hack anything.

3. How serious is each problem?

LevelWhat it meansPoints off its area's score
CriticalSomeone could take over the computer, the app or the money right now. Fix before anything else.25
HighA serious hole that's easy to abuse. Fix before going live.15
MediumA weakness that makes an attack easier or the damage bigger.5
LowGood practice that's missing. Worth fixing when you can.2
InfoA note for your awareness, not a problem by itself.0

How the score works: each area starts at 100 and loses points for every problem found in it (never going below 0). Your overall score is the average of the AI-setup areas. In a --web scan, the website code counts for half the overall score, so a badly broken website can't hide behind a perfect AI setup.

Grades: A = 90–100, B = 75–89, C = 60–74, D = 40–59, F = below 40.

4. The original scans (from AgentShield)

These run on every scan. They protect the computer you code on, and everything on it, from a badly configured or tricked AI assistant.

Area 1 · Secrets (23 checks)

What it looks for: API keys, passwords and private keys typed straight into setup files: CLAUDE.md, settings, MCP server configs, plugin files, package-manager files (.npmrc), webhook URLs with a token in them, database connection strings, keys hidden with base64, and secrets that end up in AI transcripts.

What it can do to you: anyone who sees the file, a teammate, a public GitHub repo or a stolen laptop, can use your key as if they were you. They can run up your AI or cloud bill, read your database, send messages from your WhatsApp Business number or take payments out through your Paystack account. Deleting the key from the file isn't enough: git history keeps it, so the key must be revoked and replaced.

Area 2 · Permissions & settings (67 checks)

What it looks for: settings that let the AI do too much without asking: "allow everything" rules, missing deny lists, permission prompts switched off, sandboxes disabled or given an escape hatch, destructive git commands (git push --force, reset --hard) allowed, access to sensitive folders like ~/.ssh, open network access, AI model traffic redirected to an unknown server, and plugins installed from unpinned or insecure sources. It covers Claude Code, Codex, Gemini CLI ("YOLO mode"), Hermes, OpenCode, Cursor and Copilot.

What it can do to you: permissions decide how much damage one mistake can do. With everything allowed, a single bad instruction, from a confused AI or from text an attacker planted in a web page, can delete your project, wipe your git history, read your SSH keys and passwords, or install software, all without you clicking "allow". A redirected model endpoint means every prompt and file you share could go to a stranger's server.

Area 3 · Hooks (51 checks)

What it looks for: hooks are commands that run automatically, for example every time the AI starts or uses a tool. CyberWarden flags hooks that download and run code from the internet, send data out (including over DNS, a sneaky route), open a reverse shell or network listener, add cron jobs or edit your shell profile (to come back after a restart), touch SSH keys, password stores or the clipboard, use sudo, wipe disks, change firewall rules, delete files, switch off logging, approve tool calls on your behalf, or quietly rewrite what the AI is doing.

What it can do to you: a hook runs on your computer with your permissions, every session, without asking. A malicious hook, often hidden inside a plugin or a cloned project, is basically a virus: it can steal every key and file, give an attacker a permanent back door into your machine, or destroy data. Because it runs silently, you might never notice.

Area 4 · MCP servers (41 checks)

What it looks for: MCP servers are add-ons that give the AI new tools (files, databases, browsers, APIs). CyberWarden flags known malicious or vulnerable packages, servers that run a shell or inline code, unpinned versions (npx package without a version, Docker images without a digest), connections over plain HTTP, servers open to the whole network, auto-approved tools, OAuth scopes that are too broad, and "tool poisoning": tool names or descriptions that contain hidden instructions for the AI.

What it can do to you: an MCP server is code you let the AI run. A poisoned or fake package can run anything on your computer the moment it starts. An unpinned version can turn malicious tomorrow when its author's account is hacked (a "supply-chain attack"). Plain HTTP lets anyone on the same Wi-Fi read or change the traffic. Poisoned tool descriptions can quietly steer the AI into leaking your data.

Area 5 · Agents, skills & prompt injection (57 checks)

What it looks for: agents, skills and instruction files are written in plain language, so attacks look like normal text. CyberWarden flags instructions to ignore safety warnings, send data to outside addresses, delete files, mine cryptocurrency, collect passwords in bulk, gain admin rights or stay hidden; invisible Unicode characters that hide instructions; encoded payloads; fake "end of prompt" markers; jailbreak and role-hijack wording; image links that leak data when shown; agents that can browse the web and write files (a dangerous mix); and skills that pre-approve broad tools or load unsigned code.

What it can do to you: this is "prompt injection": text that gives the AI orders you never gave. One poisoned skill or CLAUDE.md from the internet can turn your own assistant against you: it reads your secrets, sends them away, and covers its tracks, all while looking like it's helping. Invisible characters mean you can read the file and still miss the attack.

5. New: Defense-in-Depth (12 checks)

Every scan These checks look for the second line of defence: the safety nets that stop one small bug from turning into a disaster. Several are built for how apps are made in Nigeria: Paystack, Flutterwave, WhatsApp logins and the Nigeria Data Protection Act (NDPA 2023).

7. How to use it

On your computer

cyberwarden scan                                   # your AI coding setup
cyberwarden scan --path ./my-app --web             # plus your website code
cyberwarden scan --path ./my-app --web --format dashboard -o report.html

Other formats: terminal (default), json, markdown, html, sarif (GitHub code scanning) and dashboard. Add --fix to apply the safe automatic fixes after reviewing them.

On GitHub, on every push

The CyberWarden GitHub Action scans each push and pull request, marks each problem on the exact line, and can block a merge when serious problems appear. Set web: "true" to include website code.

The dashboard

One offline HTML file with: an overview (grade, score by area, what to fix first), every finding with a before/after fix, the list of checks that ran, a fix plan, the riskiest files, compliance hints (SOC 2, PCI DSS, ISO 27001; guidance, not a certified audit) and a "Learn" page. It follows light or dark mode, works on phones and can be saved as a PDF.

Extra tools for teams (from AgentShield)

  • Baseline: save today's scan, then see only what's new or fixed next time.
  • Policy: set your organisation's rules (for example "no critical findings, ever") and fail the build when they're broken.
  • Supply-chain check: verifies MCP packages against known malicious and vulnerable versions.
  • Evidence pack: a signed bundle of the scan for audits and client handovers.
  • Watch mode: re-scans while you work and alerts you to new problems.

8. Honest limits

A scanner is a smoke alarm, not a fire brigade. CyberWarden catches common, clear-cut mistakes quickly, but a clean result means "no known patterns found", not "impossible to hack". It reads code; it can't see your hosting settings, your passwords or your staff's habits.

Use it alongside code review, testing, and two-factor login on your GitHub, hosting, domain, email and payment accounts. Most real hacks start with a stolen account, not clever code.
